## 二、名词解释

| 术语 / 缩略词 | 说明 |
| --- | --- |
| 实体（Entity） | AI工作流从小说/剧本中解析提取出的结构化对象，包含角色（Character）、场景（Scene）、道具（Prop）三种类型 |
| 别名（Alias） | 小说中同一实体的不同称呼，如朱元璋的别名为"老爷子""皇上""舅舅"等 |
| 分镜（Shot） | AI工作流将剧本拆分后的最小镜头单元，包含画面描述、对白、出演实体等信息 |
| 景别（Shot Type） | 分镜的镜头类型标签，如中景、特写、全景等，由AI从 visual_description 中提取 |
| 原文依据（Evidence） | AI解析时从原文中提取的依据片段，用于让用户验证解析结果的准确性 |
| 锚点导航（Anchor Nav） | 左栏分镜导航项点击后，中栏自动滚动到对应分镜卡片，而非替换内容 |
| 悬停浮层（Popover） | 鼠标悬停资产芯片200ms后弹出的轻量预览面板，展示角色在当前分镜中的动作和状态 |
| 按需抽屉（Drawer） | 点击资产芯片后从右侧滑出的完整详情面板，默认隐藏，支持钉住为常驻面板 |
| 别名来源Tooltip | 鼠标悬停别名标签时弹出的提示，展示该别名在原文中的使用上下文和说话人 |
| 资产芯片（Asset Chip） | 分镜卡片中显示的出演资产标签，支持悬停预览和点击查看详情 |
| 剧集解析状态 | 每个剧集的解析状态标签：✓已解析（可切换）/ ⟳解析中（可点击查看进度）/ ○待解析（提示先上传） |
| glossary_index | AI输出的别名-实体ID映射表 |
| entity_refs | 分镜数据中的出演实体ID列表 |
| entities.json | AI工作流输出的实体信息文件 |
| shots.json | AI工作流输出的分镜信息文件 |
| prompts.json | AI工作流输出的图像生成提示词文件（资产管理页使用，详见功能2_资产管理页_PRD.md） |

## 三、需求背景（价值）及目标

### 1. 需求背景及价值

**用户痛点：**

- V1的剧本解析页为只读展示，用户无法直接编辑分镜内容（画面描述、对白、出演资产）
- 信息量过大导致审美疲劳——角色卡片、场景卡片、道具卡片、分镜列表全部平铺展示
- 缺少跨剧集管理能力，无法查看各集的解析状态
- 资产详情与分镜上下文缺乏关联——别名无法溯源、角色当前状态不明
- 分镜审核效率低：需要逐个点击查看，无法快速浏览和对比连续分镜
- 资产信息获取成本高：查看资产详情需要离开编辑流程，打断工作节奏

### 2. 本次需求

重构为"分镜审核工作台"，采用左栏导航+中栏可滚动分镜列表+按需抽屉的布局，核心聚焦分镜的线性审核与编辑。

**核心价值：**
- 提升分镜审核效率：可滚动浏览所有分镜，对比连贯性
- 降低信息获取成本：悬停浮层快速预览，按需抽屉深度查看
- 增强编辑体验：所见即所得，实时保存，支持插入和删除分镜

### 3. 需求目标

- 用户可通过滚动浏览所有分镜，或通过左栏锚点导航5秒内定位任意分镜
- 用户可直接编辑画面描述、对白、出演资产，实时保存
- 用户可通过悬停浮层快速确认角色在当前分镜的动作和状态，无需离开编辑流
- 用户可通过别名来源Tooltip理解每个别名的原文出处，提升AI解析结果的可验证性
- 用户可在左栏剧集列表查看各集解析状态，支持跨集切换
- 用户可插入新分镜、删除错误分镜，灵活调整分镜结构
- 将AI工作流输出的分镜数据和实体关联数据的前端利用率提升至 95%+

## 六、功能详细说明

### 1. 产品流程图

#### 1.1 剧本解析页 — 分镜审核工作台流程（v3）

```
开始：用户进入剧本解析页
    │
    ▼
系统加载 entities.json + shots.json + meta.json + prompts.json
    │
    ├──► 左栏：渲染双层导航
    │    ├── 第一层：剧集列表 + 各集解析状态标签
    │    │   └── 默认选中当前集，高亮显示
    │    ├── 统计摘要行
    │    └── 第二层：分镜锚点导航列表
    │        ├── 遍历 shots[] 渲染导航项
    │        ├── 提取景别（正则 visual_description）
    │        └── 默认高亮第一个分镜
    │
    ├──► 中栏：渲染可滚动分镜卡片列表
    │    └── 所有分镜纵向排列为卡片列表
    │        ├── 卡片头部（序号+景别+场景+时长）
    │        ├── 画面描述 → 填入 textarea
    │        ├── 对白 → 结构化表单（角色+语气+文本）
    │        ├── 出演资产 → 渲染资产芯片
    │        └── 原文依据 → 折叠按钮
    │
    └──► 悬停浮层 + 右侧抽屉：初始隐藏
    │
    ▼
等待用户交互
    │
    ├── 滚动中栏 → 左栏导航自动高亮当前可见分镜
    ├── 点击左栏分镜导航 → 中栏滚动到对应分镜卡片（锚点跳转）
    ├── 编辑画面描述 → 实时保存（带diff标记）
    ├── 编辑对白 → 实时保存
    ├── 添加/移除资产 → 更新 entity_refs
    ├── 悬停资产芯片（200ms）→ 弹出轻量浮层预览（名称+身份+分镜动作+状态）
    ├── 鼠标离开芯片 → 浮层消失
    ├── 点击资产芯片 → 右侧滑出完整抽屉
    │   ├── 抽屉展示：头像+身份+上下文卡片+别名+简介+外貌+全部出场
    │   ├── 悬停别名标签 → 弹出别名来源Tooltip（原文+说话人）
    │   ├── 点击出场分镜标签 → 中栏跳转到该分镜
    │   ├── 点击📌钉住 → 抽屉变为常驻面板
    │   └── 点击✕关闭 → 抽屉滑回隐藏
    ├── 点击左栏剧集 → 切换到该集（已解析集才可切换）
    ├── 点击折叠/展开剧集列表 → 切换剧集区域显示
    └── 点击 📖原文 → 展开/折叠原文依据
```

#### 1.2 异常逻辑

```
异常1：AI数据字段为空
  ├── 字符串为空 → 该字段区域不展示
  ├── dialogue 为 null → 对白区域展示"（本分镜无对白）"灰色斜体提示
  └── evidence 为空 → 原文依据按钮不展示

异常2：剧集为"解析中"状态
  └── 左栏剧集可点击，中栏展示骨架屏加载效果

异常3：剧集为"待解析"状态
  └── 点击后提示"请先上传内容并解析"

异常4：悬停浮层超出视口边界
  └── 自动调整浮层位置，避免被裁切

异常5：抽屉内容过长
  └── 抽屉内部滚动，头部和底部操作按钮固定
```

## 八、技术实现说明

### 1. "在当前分镜中"动作描述提取方案

#### 问题背景
AI工作流输出的数据结构中：
- `shots.json` 包含完整的 `visual_description`，但未拆分出单个资产的具体动作
- `entity_refs` 只是资产ID列表，不包含动作描述
- 悬停浮层和抽屉中需要显示"李景隆在当前分镜中呆立在镜前，表情迷茫"这样的上下文信息

**数据现状：**
```json
// shots.json - SHOT_001
{
  "visual_description": "[特写] 一面古朴的铜镜，镜面映照出一张年轻、俊朗却带着写许迷茫与陌生的男性面孔。镜头缓缓拉远，展现出郑乾（此时为李景隆身份）呆立在镜前的全景。",
  "entity_refs": ["CHAR_002", "PROP_001", "SCENE_005"]
  // ❌ 没有 entity_actions 字段
}
```

#### 方案A：前端文本提取（V2.0 实施方案）

**实现逻辑：**
```javascript
function getEntityActionInShot(shotId, entityId) {
  const shot = shots.find(s => s.id === shotId);
  const entity = entities.find(e => e.id === entityId);

  // 1. 获取完整描述
  const description = shot.visual_description;

  // 2. 分句处理
  const sentences = description
    .replace(/\[.*?\]/g, '') // 去除景别标签
    .split(/[。，；]/g)
    .filter(s => s.trim());

  // 3. 提取包含资产名称或别名的句子
  const namePatterns = [entity.name, ...(entity.aliases || [])];
  const relevantSentences = sentences.filter(s =>
    namePatterns.some(name => s.includes(name))
  );

  // 4. 返回合并结果
  return relevantSentences.join('，') || "出现在画面中";
}
```

**优点：**
- 不需要AI工作流改动，前端立即可实施
- 开发周期短，可快速上线

**缺点：**
- 提取准确性依赖正则，可能不精确

#### 2.3 数据更新逻辑
```javascript
// 用户点击"确认添加"后
function confirmAddAssets(shotId, selectedAssetIds) {
  const shot = shots.find(s => s.id === shotId);

  // 合并新选资产到 entity_refs（去重）
  shot.entity_refs = [
    ...new Set([...shot.entity_refs, ...selectedAssetIds])
  ];

  // 保存到后端
  await updateShot(shotId, { entity_refs: shot.entity_refs });

  // 刷新UI
  renderAssetChips(shot);
}
```

#### 2.4 移除资产逻辑
```javascript
// 用户点击芯片上的 × 按钮
function removeAsset(shotId, assetId) {
  const shot = shots.find(s => s.id === shotId);

  // 从 entity_refs 中移除
  shot.entity_refs = shot.entity_refs.filter(id => id !== assetId);

  // 保存并刷新
  await updateShot(shotId, { entity_refs: shot.entity_refs });
  renderAssetChips(shot);
}
```

### 附录C：局部重绘技术方案

```
局部重绘工作流：
  1. 用户点击"局部重绘"按钮
  2. 前端进入重绘模式：
     - 原图作为底层展示
     - 在上层创建透明canvas用于蒙版绘制
     - 提供画笔工具（可调大小）
  3. 用户用画笔涂抹需要修改的区域 → 生成二值蒙版图
  4. 用户输入修改描述（如"把淤伤改为更深的紫色"）
  5. 前端将原图 + 蒙版图 + 修改描述 + 原始提示词 发送到后端
  6. 后端调用 inpainting 模型 → 仅重绘蒙版区域
  7. 前端展示结果 → 用户可通过滑块对比前后效果
  8. 用户确认 → 替换原图 | 用户不满意 → 重试或取消
```

#### v1 → v2 → v3 核心变化

| 模块 | v1 | v2 | v3（当前版本） |
| --- | --- | --- | --- |
| 整体布局 | 长列表平铺 | 三栏固定布局 | 左栏导航 + 中栏可滚动列表 + 按需抽屉 |

| 字段可编辑 | 否 | 是 | 是 |
| 别名展示 | 静态标签 | 静态标签 | 悬停→来源Tooltip（原文+说话人） |
| 剧集管理 | 无 | 下拉选择 | 左栏剧集列表 + 解析状态标签 |

#### v2 → v3 设计决策理由

1. **中栏回归可滚动列表**：分镜审核是线性阅读任务，滚动比逐个点击更自然；用户可扫描相邻分镜、对比连贯性
2. **左栏改为锚点导航**：保留快速跳转能力，同时不破坏滚动浏览流
3. **右栏改为按需抽屉**：默认状态中栏满宽，空间利用率更高；需要时才展开
4. **新增悬停浮层**：降低信息获取成本，鼠标悬停即可确认"这个角色在这个分镜里干什么"，无需打断编辑
5. **新增别名来源Tooltip**：将碎片化的 evidence_excerpts 绑定到具体别名上，信息获取更精准
6. **左栏增加剧集列表**：补充跨集管理能力和解析状态可见性
