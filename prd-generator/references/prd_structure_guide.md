# PRD (产品需求文档) 标准结构指南

## 一、文档头部信息

```markdown
# 【项目名称】功能模块名称 — 产品需求文档 (PRD)

> 文档版本: vX.Y
> 创建日期: YYYY-MM-DD
> 更新日期: YYYY-MM-DD
> 所属版本: VX
> 功能模块: 模块名称
> 交互原型: 原型文件名.html
> 关联文档: 相关文档链接
```

## 二、标准章节结构

### 1. 需求变更记录

记录文档的演进历史,包含:
- 变更时间
- 变更人
- 主要变更内容

**格式:**
```markdown
| 变更时间 | 变更人 | 主要变更内容 |
| --- | --- | --- |
| YYYY-MM-DD | 姓名 | 具体变更说明 |
```

### 2. 名词解释

定义文档中使用的专业术语和缩略词,确保读者理解一致。

**格式:**
```markdown
| 术语 / 缩略词 | 说明 |
| --- | --- |
| 术语名称 | 详细解释 |
```

### 3. 需求背景及目标

#### 3.1 需求背景及价值
- **用户痛点:** 列出当前存在的问题
- **核心价值:** 说明解决方案带来的价值

#### 3.2 本次需求
简要描述本次需求的核心内容

#### 3.3 需求目标
列出可量化的目标,使用"用户可..."的句式

### 4. 产品架构

#### 4.1 功能架构
用树状结构展示功能模块层级关系

#### 4.2 信息架构
展示页面布局和信息组织方式

#### 4.3 信息层级策略 (可选)
定义不同信息的展示优先级

### 5. 需求清单

使用表格形式列出所有功能点:

```markdown
| 功能点 | 端 | 优先级 | 说明 |
| --- | --- | --- | --- |
| 功能名称 | PC端/移动端 | P0/P1/P2 | 详细说明 |
```

**优先级定义:**
- P0: 必须有,核心功能
- P1: 应该有,重要功能
- P2: 可以有,增强功能

### 6. 功能详细说明

#### 6.1 产品流程图
用文本或 Mermaid 图表描述用户操作流程和系统响应

#### 6.2 交互原型图
说明原型图文件位置和使用方式

#### 6.3 功能说明

##### 权限说明
```markdown
| 功能 | 功能权限 | 数据权限 |
| --- | --- | --- |
```

##### 查询条件说明 (如适用)
```markdown
| 查询条件 | 控件类型 | 位置 | 默认值 | 查询结果 |
```

##### 信息说明
详细描述页面/模块中的每个字段:
```markdown
| 字段 | 数据来源 | 是否可编辑 | 控件类型 | 说明 |
```

##### 按钮说明
```markdown
| 按钮 | 位置 | 触发条件 | 触发内容 | 触发结果 |
```

##### 提示信息
```markdown
| 信息类型 | 显示方式 | 消失方式 | 文案 |
```

##### 历史数据处理
说明如何处理升级/迁移场景

##### 数据需求 (含埋点)
```markdown
| 参数名 | 上报方式 | 参数说明 |
```

### 7. 非功能需求

#### 7.1 数据安全需求
```markdown
| 数据类型 | 存储安全 | 显示安全 |
```

#### 7.2 数据操作需求
- 一致性要求
- 准确性要求
- 完整性要求
- 实时性要求

#### 7.3 性能要求
列出关键操作的性能指标 (如响应时间、加载时间等)

#### 7.4 版本兼容性要求
- 浏览器兼容性
- 屏幕分辨率
- 交互设备支持

### 8. 技术实现说明

详细说明复杂功能的技术方案、数据结构、算法逻辑等

### 9. 附录

包含辅助信息,如:
- 数据字典
- API 映射表
- 正则表达式规则
- 设计演进记录

## 三、文档撰写原则

### 1. 结构化原则
- 使用清晰的层级标题 (一级标题用中文序号 "一、二、三",二级标题用数字 "1. 2. 3.")
- 善用表格组织信息
- 使用代码块展示数据结构或流程

### 2. 完整性原则
- 所有功能点都有对应的详细说明
- 异常逻辑和边界情况都有考虑
- 数据来源和去向明确

### 3. 可读性原则
- 使用图表和示例辅助说明
- 避免过长的段落,善用列表
- 专业术语在首次出现时定义

### 4. 可追溯原则
- 保留变更记录
- 关联文档清晰标注
- 数据字段明确来源

### 5. 可量化原则
- 需求目标可量化
- 性能指标具体明确
- 优先级定义清晰

## 四、常见模块模板

### 登录/注册流程模板

```markdown
#### 登录流程

1. 用户输入手机号
   - 验证:中国大陆手机号格式 (11位数字)
   - 异常:格式错误时显示提示 "请输入正确的手机号"

2. 用户点击"获取验证码"
   - 前置条件:手机号格式正确
   - 触发:发送短信验证码
   - 倒计时:60秒后可重新发送
   - 异常:发送失败时提示 "验证码发送失败,请重试"

3. 用户输入验证码并点击"登录"
   - 验证:6位数字验证码
   - 成功:跳转到首页
   - 失败:提示 "验证码错误或已过期"
```

### 列表页模板

```markdown
#### 列表页功能

**筛选条件:**
- 类型筛选: Tab 切换 (全部/类型A/类型B)
- 搜索框: 支持名称/编号模糊搜索
- 排序: 默认按创建时间倒序

**列表项展示:**
- 缩略图 (尺寸: 80×80px)
- 标题 (最多显示2行,超出省略)
- 副标题 (灰色文字)
- 元数据 (创建时间/状态标签)
- 操作按钮 (编辑/删除/更多)

**分页:**
- 每页显示: 20条
- 加载方式: 滚动加载更多

**空状态:**
- 无数据时显示: "暂无数据,点击创建"
- 搜索无结果时显示: "未找到相关内容"
```

### 表单页模板

```markdown
#### 表单页功能

**字段列表:**

| 字段名称 | 字段类型 | 是否必填 | 验证规则 | 默认值 | 提示文案 |
| --- | --- | --- | --- | --- | --- |
| 名称 | 文本输入 | 是 | 1-30字符 | 无 | 请输入名称 |
| 类型 | 下拉选择 | 是 | 枚举值 | 第一个选项 | 请选择类型 |
| 描述 | 多行文本 | 否 | 最多200字符 | 无 | 请输入描述 |

**提交逻辑:**
- 点击"保存"按钮
- 前端验证所有必填字段和格式
- 验证通过后提交到后端
- 提交成功: 提示 "保存成功" + 跳转到列表页
- 提交失败: 提示具体错误信息,停留在当前页
```

- [ ] 所有字段都明确了数据来源
- [ ] 所有按钮都说明了触发逻辑
- [ ] 异常情况和边界条件都有考虑
- [ ] 性能指标具体可量化
- [ ] 专业术语都在名词解释中定义
- [ ] 变更记录完整
- [ ] 关联文档链接正确
