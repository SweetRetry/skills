## 二、名词解释

| 术语 / 缩略词 | 说明 |
| --- | --- |
| 实体（Entity） | AI工作流从小说/剧本中解析提取出的结构化对象，包含角色（Character）、场景（Scene）、道具（Prop）三种类型 |
| 别名（Alias） | 小说中同一实体的不同称呼，如朱元璋的别名为"老爷子""皇上""舅舅"等 |
| 角色状态（State） | AI从剧情中识别的角色外观变化阶段，如"默认状态-白色素服"→"受伤状态-额头乌青"。每个状态有独立的图片生成提示词 |
| 状态触发（Trigger） | 导致角色外观状态发生变化的分镜事件，如"SHOT_004: 由于重重磕头导致额头受伤" |
| 三视图（Turnaround） | 角色的正面+侧面+背面三角度视图，用于保持角色形象一致性 |
| 多角度视图 | 场景的正面+右侧+左侧+后方四角度视图，用于建立空间认知 |
| 局部重绘（Inpainting） | 在已生成的图片上选择局部区域进行重新生成，保持其余部分不变 |
| 生命周期（Lifecycle） | 物品在不同分镜中的存在状态和变化轨迹 |
| 分镜时间线 | 横向时间轴，展示角色/物品在所有分镜中的出场情况和状态变化 |
| 提示词方案 | AI工作流为每个资产生成的4套不同风格的图像生成提示词 |
| 图片采用 | 用户从4套生成方案中选择一张作为正式资产图片 |
| prompts.json | AI工作流输出的图像生成提示词文件，包含角色多状态及对应的生成提示词 |
| entities.json | AI工作流输出的实体信息文件 |
| shots.json | AI工作流输出的分镜信息文件 |

## 三、需求背景（价值）及目标

### 1. 需求背景及价值

**用户痛点：**

- V1的资产管理页仅展示资产基础信息和已生成的图片，功能单一
- AI工作流已能识别角色在不同剧情阶段的外观状态变化（如受伤、换装），但V1未展示
- 角色有多状态多套提示词，但V1只展示一套，用户无法选择最佳效果
- 场景已有多角度提示词，但V1仅支持单角度生成，空间感不足
- 物品在不同分镜中有不同的呈现状态，但V1未展示这种时间线变化
- 无局部重绘能力，用户对生成图片不满意只能整图重新生成，效率低下
- 缺乏图片版本管理，无法对比不同生成结果

### 2. 本次需求

升级为"资产生产工作台"，围绕"理解→生成→调整"工作流，完成从AI数据到可用图片的全链路。

**核心价值：**
- 提升图片生成效率：4套方案并行生成，用户选择最佳效果
- 增强角色一致性：三视图生成，多角度保持形象统一
- 优化场景认知：4角度生成，建立完整空间感
- 精细化调整：局部重绘，精准修改不满意区域
- 可视化生命周期：物品状态变化一目了然

### 3. 需求目标

- 用户可直观查看角色在不同分镜/状态下的外观变化，并为每个状态独立生成和调整图片
- 场景支持4角度图片生成（正面+右侧+左侧+后方），用户可单独重新生成任意角度
- 物品支持生命周期可视化，展示在不同分镜中的状态变化
- 所有已生成图片支持局部重绘，精准修改不满意区域
- 支持4套提示词方案对比选择，提升图片质量
- 将AI工作流输出的提示词和状态数据的前端利用率提升至 95%+

## 六、功能详细说明

### 1. 产品流程图

#### 1.1 资产管理页 — 角色生产流程

```
开始：用户选择角色资产
    │
    ▼
加载角色数据
    ├── entities.json → 基础信息（名称/别名/身份/外貌等）
    ├── prompts.json → 状态列表 + 每个状态的提示词
    └── shots.json → 分镜描述（用于时间线展示）
    │
    ▼
渲染角色工作台
    ├── 角色头部信息
    ├── 分镜时间线（状态颜色条 + 分镜节点）
    ├── 状态Tab（默认选中第一个状态）
    └── 正面图4方案 + 三视图区域
    │
    ▼
用户工作流
    │
    ├── 查看时间线
    │   ├── 观察角色在哪些分镜出场
    │   ├── 识别状态变化的触发点（⚡标记）
    │   └── 点击分镜节点 → 查看角色在该分镜的具体描述
    │
    ├── 切换状态Tab
    │   └── 查看不同状态的外观描述和提示词
    │
    ├── 生成正面图
    │   ├── 选择提示词方案（1-4）→ 预览提示词内容
    │   ├── 点击"生成" → 调用AI生成该方案的正面图
    │   │   └── 生成完成 → 查看结果 → 满意则"采用"
    │   └── 或点击"全部生成" → 4套方案并行生成
    │
    ├── 对已生成图片进行调整
    │   ├── 不满意整体效果 → 点击"重新生成"（换种子）
    │   └── 仅局部不满意 → 点击"局部重绘"
    │       ├── 进入重绘模式：用画笔选择需要修改的区域
    │       ├── 输入修改描述（如"把淤伤改为更深的紫色"）
    │       └── 重绘生成 → 查看对比 → 确认或撤销
    │
    ├── 采用正面图后生成三视图
    │   ├── 点击"生成三视图"
    │   ├── 系统自动生成 正面+侧面+背面
    │   └── 可单独重新生成某个角度
    │       └── 对某角度不满意 → 点击该角度的"重新生成"
    │
    └── 编辑详情字段
        └── 点击"编辑信息" → 修改外貌/服饰/性格描述
```

```
开始：用户选择场景资产
    │
    ▼

    ├── 调整生成结果
    │   ├── 对某角度不满意 → 点击该角度的"重新生成" → 仅重新生成该角度
    │   └── 需要微调 → 点击"局部重绘" → 画笔选区 → 重绘
    │
    ├── 采用满意的图片

    │
    ├── 生成物品图片
    │   ├── 选择提示词方案 → 预览
    │   ├── 生成4角度图片（正面/侧面/俯视/背面）
    │   └── 单角度重新生成或局部重绘
    │
    └── 编辑物品详情
        └── 修改外观描述/功能说明
```

#### 1.4 异常逻辑

```
异常1：角色仅有1个状态
  └── 不展示状态Tab，直接展示唯一状态内容

异常2：角色无front_view_prompts
  └── 提示词区域展示空输入框，用户可手动输入

异常3：图片生成失败
  └── 图片区域展示错误提示 + 重试按钮

异常4：局部重绘区域过大（>80%面积）
  └── 提示"选区过大，建议重新生成整张图片"

异常5：物品无状态变化（仅1个默认状态）
  └── 时间线仅展示出场分镜标记，不展示状态变化标记

异常6：AI提示词数据缺失
  └── 展示默认提示词模板，用户可手动编辑

异常7：资产无已生成图片
  └── 展示占位符"待生成"，引导用户点击生成按钮

异常8：生成队列过长
  └── 提示"当前生成任务较多，预计等待X分钟"，支持取消排队
```

### 1. 数据安全需求

| 数据类型 | 存储安全 | 显示安全 |
| --- | --- | --- |
| 业务数据（AI解析结果） | 数据库存储 | 仅项目成员可见 |

| 局部重绘历史 | 数据库存储（最近5条） | 仅项目成员可见 |

### 2. 数据操作需求

- **一致性**：用户在资产管理页编辑的信息，需实时同步到剧本解析页的浮层和抽屉展示
- **一致性**：用户采用的图片，需实时更新到剧本解析页的资产芯片缩略图
- **准确性**：时间线状态颜色条需严格匹配 prompts.json 中的 states[].shots[] 映射
- **准确性**：分镜节点点击后展示的描述，需准确提取自该分镜的visual_description
- **完整性**：用户编辑不覆盖AI原始数据，保留 user_override 和 ai_original 两层
- **实时性**：图片采用后的同步延迟 ≤ 500ms
- **可追溯**：生成历史和重绘历史完整记录，支持版本回退

### 3. 性能要求

- 资产列表首屏渲染 ≤ 800ms（100个资产）
- 资产详情切换响应时间 ≤ 500ms
- 分镜时间线渲染 ≤ 300ms（100个分镜节点）
- 图片生成不阻塞页面交互（异步+进度条+取消按钮）
- 局部重绘蒙版绘制 60fps（Canvas优化）
- 图片预览加载优先级：已采用图 > 最近生成图 > 历史图
- 当资产数 > 50 时，左栏列表使用虚拟滚动优化性能
- 当生成历史 > 20 条时，仅加载最近5条，其余按需加载
- 大图加载使用渐进式加载（先低质量后高质量）
- 状态Tab切换使用缓存，避免重复加载数据

### 4. 版本兼容性要求

- **PC端浏览器：** Chrome 90+、Edge 90+、Safari 15+、Firefox 90+
- **最小屏幕分辨率：** 1280 × 720
- **窗口宽度适配：**

  - < 1024px：单栏显示，左栏折叠
- **交互设备：**
  - 支持鼠标操作（画笔、选区）

  - 支持触控屏操作（手指绘制蒙版）

- **数据兼容：** 支持V1和V2格式数据自动适配

## 八、技术实现说明

### 1. 局部重绘（Inpainting）技术方案

#### 工作流程

```
局部重绘工作流：
  1. 用户点击"局部重绘"按钮
  2. 前端进入重绘模式：
     - 原图作为底层展示
     - 在上层创建透明Canvas用于蒙版绘制
     - 提供画笔工具（可调大小10-100px）
  3. 用户用画笔涂抹需要修改的区域 → 生成二值蒙版图（黑白PNG）
  4. 用户输入修改描述（如"把淤伤改为更深的紫色"）
  5. 前端将以下数据发送到后端：
     - 原图URL
     - 蒙版图（Base64编码的PNG）
     - 修改描述文本
     - 原始提示词（用于保持整体风格）
  6. 后端调用 inpainting 模型（如Stable Diffusion Inpainting）
     → 仅重绘蒙版区域
  7. 前端展示结果：
     - 左右对比视图（原图 vs 重绘后）
     - 或滑块对比视图（可拖动分割线）
  8. 用户确认 → 替换原图 | 用户不满意 → 重试或取消
```

#### 技术要点

- **蒙版绘制优化：** 使用OffscreenCanvas + requestAnimationFrame确保60fps绘制
- **撤销/重做：** 使用Command模式存储绘制操作历史，支持多步撤销
- **选区计算：** 实时计算蒙版面积占比，超过80%提示用户
- **积分计算：** 根据蒙版面积比例计算消耗积分：`积分 = 全图积分 × (蒙版面积 / 总面积) × 调整系数`

### 2. 多角度生成一致性保障方案

#### 问题背景

场景/物品需要生成多角度图片（正面/侧面/俯视/背面），但每个角度独立生成可能导致风格不一致。

#### 解决方案

**方案A：种子锁定（V2.0 实施）**

```javascript
// 同一资产的多角度使用相同种子基础值
const baseSeed = hashCode(entityId + stateId);

// 不同角度在基础值上微调
const angles = {
  front: baseSeed,
  right: baseSeed + 1,
  left: baseSeed + 2,
  back: baseSeed + 3
};

// 调用生成API时传入对应种子
generateImage({
  prompt: frontViewPrompt,
  seed: angles.front,
  // ... other params
});
```

**优点：** 简单易实现，种子相近保证风格接近

**缺点：** 无法完全保证一致性（光线、细节可能不同）

---

**方案B：ControlNet引导（V2.1 优化）**

```javascript
// 先生成正面图并采用
const frontImage = await generateImage({ prompt: frontViewPrompt });

// 后续角度以正面图为ControlNet引导
const sideImage = await generateImage({
  prompt: sideViewPrompt,
  controlnet_image: frontImage,  // 使用正面图作为参考
  controlnet_conditioning_scale: 0.8  // 引导强度
});
```

**优点：** 一致性更高，角色特征保持统一

**缺点：** 需要模型支持ControlNet，成本略高

| prompts.json | states[].front_view_prompts[0-3] | 正面图4方案生成 |
| prompts.json | states[].turnaround_prompt | 三视图/多角度生成 |

### 附录B：积分消耗策略

| 操作 | 积分消耗 | 说明 |
| --- | --- | --- |
| 生成正面图（单张） | 10积分 | 标准尺寸（512×512或1024×1024） |
| 生成正面图（全部生成） | 30积分 | 4套方案，优惠价（原价40） |
| 生成三视图 | 25积分 | 3角度，基于已有正面图生成 |
| 生成场景多角度 | 35积分 | 4角度，场景图尺寸更大 |
| 重新生成 | 同原始生成 | 无折扣 |
| 局部重绘 | 3-8积分 | 根据选区大小：积分 = 10 × (选区面积 / 总面积) × 0.8 |

**积分不足提示：**
- 当用户积分不足时，生成按钮置灰
- 悬停提示"积分不足，需要X积分，当前剩余Y积分"
- 提供"充值"按钮快速跳转充值页
